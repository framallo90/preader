# Bardo

A book reader and narrator for Android. Open a PDF, EPUB, TXT, DOCX or a comic (CBZ, CBR, CB7, CBT) and read it or listen to it while you look at the real page — the narration knows which page it is on and turns it for you. Everything happens on the phone: no server, no accounts, no API keys and no connection. Books open instantly, like ReadEra.

*(Versión en español: [README.md](./README.md))*

---

## Features

- **Real visual reader** — PDF pages are drawn on the phone exactly as they are (images and layout included), fitted to the screen width, with continuous scroll, a page scrubber, fullscreen and automatic cropping of white margins.
- **Scanned PDFs** — a PDF without text still opens in visual mode; it just has no voice.
- **Page-synced narration** — while audio plays, the page being read is marked (`🔊 N`) and the view turns pages on its own. If you scroll away, a chip takes you back to where the voice is.
- **On-device voice, offline** — audio is generated by Android's text-to-speech engine. The best installed voice is picked automatically for each book's language, or you can pin one in Settings. It keeps playing with the screen locked, with notification controls, a 15 s rewind and a sleep timer.
- **One position, two ways to experience it** — reading and listening share the same character offset; switch modes and resume exactly where you left off.
- **Bookmarks, quotes and notes** — `🔖` marks where you are; long-press a paragraph or a page to save a quote or a note.
- **About this book** — one screen per book: star review, lists (To read / Read / Favorite), collections, table of contents and every annotation, each jumping straight to its place.
- **Library** — folder scanning (with excluded subfolders), filters by list and collection, real covers, grouped by folder in natural order. Each book is identified by a content fingerprint, so progress survives renames and moves.
- **Real table of contents** — uses the PDF's own outline when present; otherwise detects chapters from the text (including POV headings like `BRAN (1)`).
- **Search in book** — accent- and case-insensitive, jumping to the result.
- **Reading themes** — day, sepia and night, applied to PDF pages too, plus a dimmer that goes below the system's minimum brightness.

## Stack

| Layer | Technology |
|---|---|
| App | React Native + Expo SDK 55 + TypeScript |
| Navigation | Expo Router (file-based) |
| Database | SQLite via `expo-sqlite` |
| PDF (render, text, outline, cover, crop) | Own native module `modules/bardo-pdf` — Android `PdfRenderer` + native Pdfium for text |
| Comics (CBZ, CBR, CB7, CBT), EPUB (zip + HTML→text), SAF scanning and file fingerprints | Own native module `modules/bardo-archive` — `java.util.zip` + native 7-Zip (RAR 4/5, 7z, tar) + own HTML converter (`HtmlText.kt`) |
| Voice | Own native module `modules/voice-synthesizer` — Android `TextToSpeech.synthesizeToFile` |
| Playback | `expo-audio` (background + lock screen) |
| EPUB / DOCX parsing | `jszip` / `mammoth` |
| Tests | Vitest (pure functions) |

The app **requires a development build** (EAS or `expo run:android`): it ships its own native modules, so it does not run in Expo Go. After changing anything under `modules/` the build must be recompiled.

## Setup

```bash
npm install

# Dev with a connected device (instant JS reload after the first build)
npx expo run:android

# APK for internal testing
eas build --profile preview --platform android

# Type-check
npm run typecheck

# Tests (pure functions, no device)
npm test
```

There are no keys or services to configure.

## Architecture

### Data model

```
Book  ── status · favorite · rating · review
 ├── Chapter            from the PDF outline or detected from the text
 ├── Note               bookmark | quote | note  (one table, told apart by type)
 ├── ReadingProgress    character offset + percentage
 └── Collection  (N:N)  a book can belong to several
```

Progress, voice, search and annotations share one unit: the **character offset within the book's text**. That is what lets reading and listening share a single position. For PDFs, `pageOffsets` (where each page starts inside the text) translates between offset and page both ways.

### Opening a book

```
PDF
  → bardo-pdf: opens the document ONCE (temp-file backed memory)
       · per-page text + title/author + outline
  → joinPdfPages: drops repeated headers/footers, joins paragraphs split by a
                  page break, builds fullText + pageOffsets
  → page aspect + content box (margin crop)
  → local cache (SQLite if small; files on disk if large)
  → pages are drawn on demand, only the ones on screen

EPUB / TXT / DOCX  → local parser → fullText → text blocks
```

### Audio

```
fullText → short chunks that always end at a sentence boundary (synthesisSegments)
  → voice-synthesizer: Android's TTS engine writes one WAV per chunk
  → expo-audio plays it; the next two chunks are prepared ahead of time
  → playback position is translated to character offset → page
```

The player works with files, which is why background playback, lock screen, seek and rewind behave like any other audio.

### Page rendering

`PdfPageList` requests each page from `pdfLocalService`, which keeps a **LIFO queue with cancellation**: fling through a hundred pages and what is on screen is drawn first, while requests for pages that already left are dropped. Rendered pages are cached on disk with a size cap.

## Project layout

```
app/                  screens (Expo Router)
  index.tsx             library
  reader.tsx            reader (pages or text) + voice
  book.tsx              "About this book"
  settings.tsx          settings
modules/
  bardo-pdf/            native PDF: render, text, outline, crop
  voice-synthesizer/    system TTS to a WAV file
src/
  components/           PdfPageList, ReaderBlockCard, BookGridItem…
  hooks/                useReaderController, useAppSettings
  services/             parsers, pdfLocalService, systemTtsService, playback, scanning
  storage/              SQLite repositories (books, notes, collections, progress, cache)
  utils/                tested pure functions (pageMap, pdfPages, voices, textSearch…)
docs/research/        ReadEra teardown and parity plan
```

## Conventions

- Code comments and UI strings are in Spanish.
- Logic that can be tested without a device lives in `src/utils/` as pure functions with a `.test.ts` next to it.
- Schema migrations go in `runMigrations` (`src/storage/database.ts`), versioned with `PRAGMA user_version`.
